# Groundedness model card (PR 9.2)

Research only. Never a buy/sell/hold recommendation. A checker
verdict of PASS means the memo's numbers trace to the run's tool
outputs — it is not a claim that the memo's thesis is right, and
it never counts as a validated prediction. LLM output never counts
as a validated prediction.

## Protocol

Pre-registered in `docs/round-9-protocol.md` on branch
`round-9-foundation` (commit
`2d4df35b88568771ec1ffab6ef25908450390fc6`), **before** any Round 9
implementation existed. The protocol fixed the thresholds before
any fixture ran: the checker must block 100% of fixture memos
containing any unsourced number (0 false passes) AND pass at
least 95% of the fully-grounded fixture memos AND agree with the
risk gate on at least 90% of fixture runs AND beat both baselines
(no checker, keyword-only). Anything less is "no edge". No
parameter, threshold or fixture was tuned after seeing results.
No protocol amendment was needed for this item.

Reproduce with:

```text
python3 scripts/generate_groundedness_fixtures.py
python3 scripts/evaluate_groundedness.py --date 2026-11-28
```

## Implementation

`toolkit/groundedness.py` (stdlib only): `check_memo(memo, events)`
is a pure function over (memo text, event log) and the contract
item 9.3's dossier pipeline builds against. It returns a
JSON-serialisable dict with `verdict` (`PASS`/`BLOCK`), per-check
results for `structure`, `groundedness`, `sources` and
`gate_agreement`, `numbers_checked` / `numbers_grounded`,
`gate_verdict` (the log's verdict, verbatim) and `reasons` (every
BLOCK names its token, section, source entry or gate mismatch).
The checker does not generate text, does not call an LLM, does
not edit the memo and does not fetch anything.

### Number grammar (fixed in the module docstring before the first fixture)

A numeric claim is an optional sign, an optional currency symbol
(`$`, `€`, `£`), digits with optional thousands separators
(groups of exactly three), an optional decimal fraction, and an
optional unit suffix `%` or `x`. The currency symbol is
presentation only; the unit suffix is part of the claim (a `%`
claim matches only `%` evidence). Not claims, and masked before
extraction: ISO dates, filing labels (`10-K`, `10-Q`, `8-K`,
`20-F`), standalone years (1900–2099) and section ordinals
(`Section 3`). A token leading with a valid number followed by
`-` and letters contributes that number (`30-close` claims 30).
Quarter/half labels (`Q1`–`Q4`, `H1`, `H2`), fiscal-year labels
(`FY25`), index names (`S&P500`) and version labels (`v2.0`) are
proper names, not claims. Anything else containing a digit is
unparseable and blocks the memo fail-closed, naming the token
(`147..00`, `1,23,456`, `Rs129.00` — write `Rs 129.00`).

### Rounding tolerance (fixed)

A memo number matches an evidence number when the units agree
and the absolute difference is at most `max(1% of the evidence
value, 0.005)`. So `12.5%` matches evidence `12.54%` (0.32% off)
and `42.9%` does not match `42.36%` (1.27% off).

### Evidence (the only sources of truth)

Numeric values carried by `evidence_ref` and `tool_result` events
from the same run: every int/float field except `seq`, plus every
grammar number inside their string fields (`source`, `detail`).
Numbers in any other event type — the `gate_result` reason
included — are NOT evidence. Structure: all five sections must be
present as headings (thesis, key risks, what would change my
mind, gate verdict, sources). Sources: every entry under Sources
must match an `evidence_ref` source from the same run. Gate
agreement: the memo's stated gate verdict must equal the last
`gate_result` verdict in the log. Note the checker judges the
MEMO, not the trade: a memo that faithfully reports a BLOCKed
gate passes; what never passes is a memo that claims PASS on a
BLOCKed run (or BLOCK on a PASSed run).

## Results — run 2026-11-28

Run by `scripts/evaluate_groundedness.py` (full per-fixture table
above; machine-readable record in
`docs/groundedness-eval-results.json`). Memos reached the checker
through the FakeProvider only (26 calls, 780 tokens at a fixed
10 input + 20 output per call; no network, no real key).

- **Checker correct: 26/26 (100%). False passes: 0. False blocks: 0.**
- **Grounded pass rate: 11/11 (100%, need ≥95%).** The 11
  expected-PASS fixtures are the 8 grounded, the 2 rounded-in and
  the gate-blocked-honest memo.
- **Planted block rate: 6/6 (100%). Unsourced block rate: 15/15
  (100%, need 100%).** Every expected-BLOCK fixture was blocked,
  each naming its token, section, source or mismatch.
- **Gate agreement: 24/26 (92.3%, need ≥90%).** The 2
  disagreements are the two designed gate-mismatch fixtures
  (memo claims PASS on a BLOCKed run, and BLOCK on a PASSed run);
  every other fixture's memo states the log's gate verdict.
- **Baselines: no-checker 11/26 (42.3%), keyword-only 12/26
  (46.2%).** The checker (100%) beats both. The keyword baseline
  passes every memo with a Sources heading, which is all but one;
  the one it blocks (missing-section-02, no Sources section) is
  the only fixture it gets right that the no-checker baseline
  does not.

**Verdict: win.** All four pre-registered conditions hold
(0 false passes, 100% grounded pass, 92.3% gate agreement, beats
both baselines).

## Known gaps

- The grammar cannot parse magnitude suffixes (`1.2m`, `385bn`)
  or ranges (`120–147` reads as two claims, 120 and 147); a memo
  using them is blocked fail-closed, which is safe but noisy for
  real memos that cite millions/billions.
- Tolerance is purely relative (1%): on very small numbers the
  0.005 absolute floor dominates, so `0.25` vs evidence `0.254`
  passes while `0.25` vs `0.26` blocks — the floor, not the
  relative gap, decides there.
- Units must match exactly: a memo citing plain `3.2` where the
  evidence is `3.2%` blocks, even when a human would read it as
  the same number. Currency symbols are ignored, so `$129.00`
  matches a plain `129.00` evidence value.
- The checker matches numbers, not labels: a memo that attaches
  the right number to the wrong label (revenue's value cited as
  net income) passes if both numbers happen to be in evidence.
  Label-aware matching is a 9.3 follow-up, not claimed here.
- All 26 fixtures share one synthetic evidence set and one
  DEMO symbol: the suite proves the checker against its own
  grammar, not against the variety of real memos. No live LLM
  output was checked, and no real-company memo is claimed
  grounded on this strength.
- Gate agreement is measured on the memo's stated verdict, not
  on the checker's verdict: a gate-BLOCKed run can still produce
  a checker-PASS memo when the memo faithfully reports the block.
  Consumers that must refuse gate-blocked runs should read the
  `gate_verdict` field and apply their own rule.

## What still keeps this from being the most advanced, and why

The checker is a value-matching gate, not a truth machine: it
verifies that a number appears in the run's tool outputs, not
that the tool output was right, the label is right, or the
reasoning is sound — a memo can pass with every number sourced
and still be wrong. It only speaks the one synthetic evidence set
it was tested on, and real memos cite millions, ranges, ratios
and derived numbers its grammar blocks or misreads. Until it is
run against real agent memos with real event logs (9.3's dossier
pipeline, on fixture companies first), the "win" above is a
win on fixtures, not evidence the programme's memos are grounded.
